RimPedia is a dynamic in game encyclopedia for RimWorld.

It builds its pages from the mods you currently have loaded. If your mod list changes, RimPedia changes too.

RimPedia was originally made for Medieval Overhaul. It was made because people kept asking the same questions. Where does this item come from? What is this corpse used for? How do I unlock this research? RimPedia tries to answer these questions directly in game.

It is not limited to Medieval Overhaul. It works with any mod list. Medieval Overhaul just has some extra support because that is where the project started.

[*]Click a heading to fold the section away
[*]Rows are links, they open the page behind them

Most pages answer two simple questions. Where does this come from, and what is it used for. Entries are linked to each other, so you can follow a chain step by step. For example, from a research project to its required schematic, and from that schematic to the ruin where it can be found.

RimPedia works with vanilla, DLC content and modded content.

Most normal Def based content is picked up automatically. This includes things like items, recipes, research, buildings, traders and many other common systems.

Some custom mechanics use their own custom mod extensions or other special code. RimPedia reads those too and links what belongs together, but it cannot always tell what a mechanic means. Because of that, some mods may need extra support for certain mechanics. Luckily, this is not needed very often.

If a mod is missing something important, please tell me. I can have a look and maybe add support for it.

[img]https://raw.githubusercontent.com/EvilEyeGuy/RimWorld-RimPedia/workshop/h7_reads.png?v=1[/img]

A page can show if something comes from Core, Royalty, Ideology, Biotech, Anomaly, Odyssey or from a mod.

For Medieval Overhaul, RimPedia also reads several custom mechanics that are not easy to see in normal gameplay. This includes things like monster drop chances, loot chances, schematic requirements, mimic containers and Explorer's Workbench discoveries.

Ruins and hideouts are shown as floor plans, and different layouts are shown as separate tabs. Because this can spoil what is inside, floor plans start blurred by default. You can reveal them with a click or disable the blur in the mod settings.

[img]https://raw.githubusercontent.com/EvilEyeGuy/RimWorld-RimPedia/workshop/05_performance.png?v=2[/img]

Measured with Dubs Performance Analyzer on a paused colony, on the heaviest page in the list, at the same window size as the vanilla tabs.

RimPedia does not build its index during game startup. The index is built the first time you open RimPedia in a session. On large mod lists this may take a moment, so it runs as a loading screen with progress. If you never open RimPedia, it does not do this work.

After the index is built once, opening it again is instant for the rest of the session.

With the heaviest page open, drawing cost is about 1 ms per frame. The compact view costs much less and can usually be left open without problems.

[b]Does RimPedia require Medieval Overhaul?[/b]
No. It works with any mod list.

[b]Does it spoil ruins?[/b]
Floor plans are blurred by default.

[b]Does it slow down startup?[/b]
No. The index is built when you open RimPedia.

[b]What if a mechanic is missing?[/b]
Tell me and I can look into it.
